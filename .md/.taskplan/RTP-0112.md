# RTP-0112 — excluirLancamento: validar o id como uuid antes da RPC

Reserva: Livre
ID no TASK.md: RTP-0112 · Lote: Refatoração Lote-20 · Agente: executor · Chapéu: Frontend · Est: 0.5h · Dep: TP-0106 · Status no TASK.md: Pendente
Reqs: G-05; origem: DevSecOps de TP-0106 (não crítico, baixo) · Aceite: `excluirLancamento` recusa id que não é uuid com `registro_invalido` sem chamar a RPC, como `alterarDataParcela`; teste unitário cobre id inválido e válido.

## 1. Plano de execução
Em `dados/comandos/lancamentos.ts`, acrescentar `if (!ehUuid(id)) throw { tipo: 'regra', codigo: 'registro_invalido' }` antes de `chamarRpc`, igual a `alterarDataParcela`. Hoje o id vem do lançamento já lido (validado em `consultas/lancamento.ts`), então é defesa em profundidade.

## 2. Plano de teste
`npx vitest run lancamentos.test.ts`: id inválido não chama a RPC e dá `registro_invalido`; id válido chama.

## 3. Plano de validação de segurança
Confirmar no diff que a recusa é local e a mensagem é a mesma do inexistente (G-05).
