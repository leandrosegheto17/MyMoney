# RTP-0113 — T11: useMeta não consulta metas com id malformado

Reserva: Livre
Origem: DevSecOps de RTP-0102 (baixa). RTP-0102 guardou `useMovimentosMeta` com `enabled: ehUuid(metaId)`, mas `useMeta` (ganchos/useMetas.ts) ainda dispara `buscarMeta` com `id=eq.abc` para id de rota não-uuid (erro 22P02 do Postgres, tratado como erro de dados).

## 1. Plano de execução
Em `useMeta`, adicionar `enabled: ehUuid(id)` (import de `../dados/uuid`). Conferir que `useDetalheMeta` segue tratando id não-uuid como `naoExiste` e que outros usos de `useMeta` não quebram.

## 2. Plano de teste
`Meta.test.tsx`: id `abc` -> `buscarMeta` e `buscarMovimentosMeta` não chamados; `useMetas.test.tsx` segue passando.

## 4. Resultado da execução
Feito: `useMeta` ganhou `enabled: ehUuid(id)`. `useDetalheMeta` já trata id não-uuid como `naoExiste`; `MetaFormulario` só chama `useMeta` com uuid.
Arquivos alterados:
- frontend/web/src/ganchos/useMetas.ts
- frontend/web/src/ganchos/useMetas.test.tsx (teste de id malformado; o teste de erro de regra passou a usar uuid, pois 'abc' agora não consulta)
- frontend/web/src/paginas/Meta.test.tsx (assert de `buscarMeta` não chamado)
Testes: `npx vitest run src/paginas/Meta.test.tsx src/ganchos/useMetas.test.tsx src/paginas/MetaFormulario` -> 40 passando, 0 falhando.
Checklist de convenções: sem duplicação, sem IDs de tarefa em código, arquivos pequenos, sem import que fure fronteiras. Sem dúvidas/riscos.

## 3. Plano de validação de segurança
Id malformado não gera requisição ao banco; mensagem igual à de inexistente/alheia (G-05).
