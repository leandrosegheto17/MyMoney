# RTP-0154 — Expor só o schema api no painel de produção e corrigir a conferência (origem TP-0010)

Reserva: Livre
Status-local: Concluída · aguarda QA
Grupo: Refatoração Lote-2
Origem: QA da TP-0010. (1) O aceite pede "schemas expostos só `api`", mas o schema não existe antes do TP-0011 (que depende do TP-0010); a conferência ficou "parcial" com Exposed schemas = nenhum. (2) `conferencia-painel.md` diz que o `config.toml` não define `extra_search_path`, mas define `["extensions"]`; o painel tem `public, extensions`.

## 1. Plano de execução
Depois do TP-0011 (e antes ou junto do TP-0012), com o usuário: Integrations > Data API > Settings > Exposed schemas = só `api`. Atualizar a linha "Schemas expostos" e a seção "Pendência" de `conferencia-painel.md`; incluir linha de `extra_search_path` (painel × `config.toml`) e resolver a divergência (tirar `public` do painel ou ajustar o `config.toml` com justificativa). Reexecutar os curl e registrar. **Reaproveitamento:** editar o arquivo existente; `config.toml` segue como fonte.

## 2. Plano de teste
Com a anon: `Accept-Profile: public` recusado; `Accept-Profile: api` aceito; `POST /graphql/v1` sem dados; `rpc/ping` devolve 1; `/auth/v1/settings` ainda com `disable_signup: true`.

## 3. Plano de validação de segurança
G-02: só `api` exposto, `public` e `graphql_public` fora; arquivo sem chave anon/`service_role`/senha.
