## 1. Plano de execução
**Reaproveitamento:** USAR schemas `app`/`api`, `schema_paths` e privilégios padrão do TP-0003 (as funções novas já nascem sem `execute` para `public`/`anon` e com `execute` para `authenticated`; não repetir grants). Padrão de pgTAP do TP-0003. Estas 3 funções são o módulo comum que TP-0015, TP-0061 e TP-0120 vão USAR; nenhum outro lugar calcula "hoje" ou "dia no mês" (TASK 1.3, D-13).
**Camada:** `backend/supabase/schemas/app/funcoes/` (`hoje.sql`, `dia_no_mes.sql`, `inicio_mes.sql`), um arquivo por função; pgTAP em `backend/supabase/tests/`.
**Referência visual:** não se aplica.

1. TDD: escrever os 3 arquivos pgTAP (passo de teste) e ver falhar.
2. `app.hoje(p_instante timestamptz default now()) returns date`: `(p_instante at time zone 'America/Sao_Paulo')::date`; `stable`. O parâmetro com default é o que permite testar 23h30 de 31/12 sem trocar o relógio; os consumidores chamam `app.hoje()` sem argumento. Interpretação registrada (desvio pequeno).
3. `app.inicio_mes(p_data date) returns date`: `date_trunc('month', p_data)::date`; `immutable`.
4. `app.dia_no_mes(p_mes date, p_dia integer) returns date`: `p_mes` é qualquer data do mês (normaliza com `app.inicio_mes`); devolve `inicio + least(p_dia, último dia) - 1`; `immutable`. `p_dia` fora de 1..31 ou nulo → `raise exception 'valor_invalido'` (código da lista do SDD §2; interpretação registrada: o aceite não diz o que fazer com dia inválido).
5. Todas: `language sql` (ou plpgsql só em `dia_no_mes`, por causa do `raise`), `security invoker`, `set search_path = ''`, nomes qualificados (`app.inicio_mes`, `pg_catalog` implícito), parâmetros `p_*` (TASK 1.3). Exceção ao "primeira linha `app.membro_atual()`": funções puras de data, sem acesso a dados (e `membro_atual` só nasce no TP-0013).
6. `pnpm exec supabase db diff --workdir backend -f utilitarios_de_data`; envolver em `begin; … commit;`; `pnpm local:resetar` do zero.
7. NÃO fazer: usar `current_date` (depende do `TimeZone` da sessão, que no Supabase é UTC), expor em `api`, criar `app.fim_mes` ou outros utilitários não pedidos.

## 2. Plano de teste
Arquivos (um por regra, TASK 1.3): `tests/datas/hoje.sql`, `tests/datas/dia_no_mes.sql`, `tests/datas/inicio_mes.sql`.
- `hoje`: `app.hoje('2026-12-31 23:30-03')` = `2026-12-31` (em UTC já é 01/01); `app.hoje('2027-01-01 02:59Z')` = `2026-12-31`; `app.hoje('2027-01-01 03:00Z')` = `2027-01-01`; `app.hoje()` = `(now() at time zone 'America/Sao_Paulo')::date` com `set local timezone = 'UTC'` e com `'Asia/Tokyo'` (não depende do fuso da sessão).
- `dia_no_mes`: (2026-02, 31) → 2026-02-28; (2028-02, 31) → 2028-02-29 (bissexto); (2100-02, 29) → 2100-02-28; (2026-04, 31) → 2026-04-30; (2026-12-15, 10) → 2026-12-10; (2027-01, 31) → 2027-01-31 (virada de ano); dia 1; `p_dia` 0, 32 e nulo → `throws_ok(…, 'valor_invalido')`.
- `inicio_mes`: 2026-12-31 → 2026-12-01; 2028-02-29 → 2028-02-01; 2027-01-01 → 2027-01-01.
- Privilégio: `has_function_privilege('anon', 'app.hoje(timestamptz)', 'execute')` = false; `authenticated` = true.
- Comandos: `pnpm local:resetar`; `pnpm exec supabase test db --workdir backend` (estes 3 + `seguranca/00-privilegios.sql`, afetado). `contrato:gerar` e CI do banco ainda não existem (TP-0019, TP-0018): registrar como não aplicável em `## 4`. [BD]: exclusivo.
