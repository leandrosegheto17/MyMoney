3. `api.contexto() returns jsonb`, `language plpgsql` (ou `sql`), `security invoker`, `set search_path = ''`, `stable`, primeira linha `app.membro_atual()` (TASK 1.3).
   - `membro.id`/`nome`: `app.membro` onde `id = app.membro_atual()`.

   - `outro_membro.nome`: a outra linha de `app.membro` visível pela RLS; sem segundo membro → `outro_membro: null` (registrar).
   - `mes_corrente` = `app.inicio_mes(app.hoje())`; `hoje` = `app.hoje()`. Nunca `now()`/`current_date` direto.
4. Usuário sem membro: `app.membro_atual()` nulo → `raise exception 'registro_invalido'` antes de qualquer leitura.
   RESOLVIDO (Coordenador, 2026-10-09): regra única para todo o schema `api`: usuário autenticado sem linha em `app.membro` recebe `registro_invalido` de qualquer função `api.*` (leitura RPC ou escrita), como primeira verificação; as views voltam vazias pela RLS. No app, `registro_invalido` no `contexto` é tratado como erro de leitura (estado de erro padrão), sem tela própria. Registrado no SDD §2 ("Contrato da API", códigos de erro) e no aceite do TP-0015.
