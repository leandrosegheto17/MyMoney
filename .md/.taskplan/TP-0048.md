2. `schemas/app/tabelas/conta.sql`: `id uuid pk default gen_random_uuid()`, `lar_id uuid not null default app.lar_atual() → app.lar`, `dono_id uuid not null default app.membro_atual() → app.membro`, `nome text not null check (btrim(nome) <> '')`, `saldo_inicial_centavos bigint not null default 0` (sem `> 0`: saldo inicial pode ser 0; negativo fica a critério do `salvar_conta`, TP-0054), `arquivada boolean not null default false`, `criado_em timestamptz default now()`. **`unique (id, dono_id)`**: alvo dos FKs compostos que garantem "conta do mesmo dono" em `movimento_conta` (aqui), `forma_pagamento` (TP-0049) e `lancamento_pagamento` (TP-0051). Índice `conta(dono_id)`.
3. `schemas/app/tabelas/movimento_conta.sql`: `id`, `lar_id`, `dono_id` (defaults como acima), `conta_id uuid not null`, FK composto `(conta_id, dono_id) → app.conta(id, dono_id)`, `tipo text not null check (tipo in ('ajuste','aporte','retirada','pagamento_cartao'))`, `sentido text not null check (sentido in ('entrada','saida'))`, `valor_centavos bigint not null check (valor_centavos > 0)` (ADR-004: valor sempre positivo, o sinal é o `sentido`), `data date not null`, `criado_em`. Coerência opcional por `check`: `aporte` → `saida`, `retirada` → `entrada`, `pagamento_cartao` → `saida` (RN-12); `ajuste` aceita os dois. Índice `movimento_conta(conta_id, data)` (saldo, TP-0064). **Não** criar `forma_credito_id` (TP-0049) nem `movimento_meta_id` (TP-0144).
4. RLS `enable` + `force` nas duas. Políticas por comando (`select`, `insert`, `update`, `delete`) com `dono_id = app.membro_atual()` (e `with check` também `lar_id = app.lar_atual()`), nunca lendo `app.membro`. `grant select, insert, update, delete … to authenticated` (as funções `api.*` são `security invoker` e escrevem como o membro; a tabela não é exposta porque só o schema `api` é publicado, G-02). Nada para `anon`.
5. `seeds/02-contas.sql`: contas de Leandro com os ids e valores de `.md/mockup/respostas/contas.json` (`…0201` Nubank 250000, `…0202` Itaú 80000) e 1 conta fictícia de Ana (id da mesma faixa, ex. `…0211`, registrar em `## 4`), mais 1 `movimento_conta` de ajuste por membro, para o isolamento ter dado nos dois lados. Inserir com `dono_id`/`lar_id` explícitos (o seed roda sem JWT).
6. `supabase db diff -f contas_e_movimentos`; completar à mão políticas e grants que o diff não capturar (lista no `backend/README.md`, TP-0003); `begin; … commit;`; `pnpm local:resetar` do zero.
