## 1. Plano de execução
**Reaproveitamento:** USAR o projeto `backend/supabase/` e os scripts `pnpm local:resetar` do TP-0002; editar `backend/supabase/config.toml` só para acrescentar `[db.migrations] schema_paths`. **Camada:** `backend/supabase/schemas/` (fonte declarativa), `backend/supabase/migrations/` (gerada), `backend/supabase/tests/seguranca/` (pgTAP). TASK 1.3: um arquivo por objeto.
**Referência visual:** não se aplica.

1. Fonte declarativa: `schemas/app/schema.sql` (`create schema app;` + grants de schema) e `schemas/api/schema.sql` (idem). `schemas/privilegios_padrao.sql` com os `alter default privileges`. No `config.toml`, `[db.migrations] schema_paths` em ordem explícita: schemas primeiro, depois privilégios, depois `app/**`, depois `api/**` (a ordem importa para as tarefas seguintes).
2. Grants (ADR-002 §3, SDD §7 item 2): `revoke all on schema app from public, anon;` `grant usage on schema app to authenticated;` `revoke all on schema api from public;` `grant usage on schema api to authenticated;`. **Não** conceder nada a `anon` em `api` aqui: o `usage` de `anon` em `api` entra com o `api.ping` no TP-0005 (único recurso do `anon`).
3. Privilégios padrão, `for role postgres` (papel que aplica as migrations; conferir com `select current_user` no `db reset`): `alter default privileges for role postgres revoke execute on functions from public;` (global, é o que impede o `anon` de herdar via `PUBLIC`) e `… in schema app, api revoke execute on functions from anon;`. Interpretação registrada (desvio pequeno): sem `PUBLIC`, nenhuma função nova seria executável por `authenticated`; para as tarefas seguintes não repetirem `grant`, acrescentar `alter default privileges for role postgres in schema app, api grant execute on functions to authenticated;` e anotar no `backend/README.md`. Grants de tabela ficam para o TP-0013 (não decidir aqui).
4. Migration: `pnpm exec supabase db diff --workdir backend -f schemas_e_privilegios` (sem ID de tarefa no nome). Conferir o que veio; o que faltar (grants, `alter default privileges`) é escrito à mão na mesma migration, tudo dentro de `begin; … commit;` (TASK 1.3). `pnpm local:resetar` do zero.
5. `backend/README.md`, seção "O que o `db diff` captura": testar de fato com objetos descartáveis (uma política, um `grant`, uma view com `security_invoker = true`, `alter default privileges`) e registrar o resultado de cada um (capturado / escrito à mão), apagando os objetos de teste. É o insumo que TP-0013 e seguintes usam (risco do TASK §2).
6. NÃO fazer: tabelas, funções, `api.ping`, mexer no schema `public` além do necessário.
