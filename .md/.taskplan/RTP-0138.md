# RTP-0138 — Fixar fim de linha LF nos scripts .sh com .gitattributes

Reqs: achado não crítico do QA do TP-0009; shellcheck no CI do TP-0008 · Aceite: existe `.gitattributes` na raiz com `*.sh text eol=lf`; num checkout no Windows `shellcheck backend/operacao/**/*.sh` roda sem SC1017 (hoje os `.sh` ficam com CRLF no worktree e LF no índice) e os testes bash seguem verdes

## 1. Plano de execução
**Reaproveitamento:** nada a reaproveitar; não há `.gitattributes` no repositório. Criar na raiz com `*.sh text eol=lf`; depois `git add --renormalize backend/operacao` e conferir `git ls-files --eol` (w/lf nos `.sh`). Avaliar se `*.bats`/outros scripts de operação precisam da mesma regra.
**Camada:** raiz do repositório (configuração).
**Referência visual:** não se aplica.

## 2. Plano de teste
- `git ls-files --eol backend/operacao | grep '\.sh'` → todos `i/lf w/lf`.
- `shellcheck backend/operacao/setup/*.sh backend/operacao/comum/*.sh` sem SC1017.
- `bash backend/operacao/setup/testes/limpar-supabase.test.sh` → 0 falhas.

## 3. Plano de validação de segurança
Não toca superfície de segurança.

## 4. Resultado da execução
- Criado `.gitattributes` na raiz com `*.sh text eol=lf`. `git add --renormalize backend/operacao` não alterou o índice (já LF). Os `.sh` de `backend/operacao` estavam CRLF no worktree e foram convertidos para LF (`sed -i 's/\r$//'`); `git diff` sem diferença de conteúdo.
- Testes: `git ls-files --eol backend/operacao | grep '\.sh'` → todos `i/lf w/lf`; `shellcheck backend/operacao/setup/*.sh backend/operacao/comum/*.sh` → saída vazia, exit 0 (sem SC1017); `bash backend/operacao/setup/testes/limpar-supabase.test.sh` → 8 casos, 0 falhas.
- Só `*.sh` precisou da regra (não há `.bats` nem outros scripts em operação).
- Risco/observação: `backend/supabase/volume/carregar.sh` e `testes/carregar.test.sh` seguem CRLF no worktree (fora do escopo; um novo checkout já vem LF). `git status` pode listar os `.sh` como `M` por cache de stat, sem diff de conteúdo.
