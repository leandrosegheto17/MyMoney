## 1. Plano de execução
**Reaproveitamento:** USAR `app.lancamento`, `app.lancamento_pagamento` (TP-0051), `app.forma_pagamento.tipo` (TP-0049), `app.membro_atual()`/`app.lar_atual()` (TP-0013). Esta regra é o módulo único de "quem pode mudar o quê": `api.editar_lancamento` (TP-0099) a usa; `api.alterar_data_parcela` (TP-0117) deve usar o campo `parcelas` daqui em vez de reescrever "só o pagador".
**Camada:** banco, `backend/supabase/schemas/app/funcoes/permissoes_edicao.sql` (função interna `app.*`, não exposta); pgTAP em `backend/supabase/tests/lancamentos/`.
**Referência visual:** não se aplica.

Assinatura: `app.permissoes_edicao(p_lancamento_id uuid) returns table (descricao boolean, valor boolean, data boolean, categoria_mesmo_escopo boolean, troca_escopo boolean, forma boolean, parcelas boolean)` (uma linha); `stable`, `security invoker`, `set search_path = ''`; 1ª linha `v_membro := app.membro_atual()` (nulo → `registro_invalido`).
3. Leitura com checagem **explícita** de visibilidade (a função roda dentro do DEFINER do TP-0099, onde a RLS não protege): `l.lar_id = app.lar_atual() and (l.escopo = 'conjunto' or l.dono_id = v_membro)`; não achou → `registro_invalido` (G-05).
4. Matriz (RN-05: quem lança é o pagador, então "pagador", "dono" e "quem lançou" = `l.dono_id`):
   - `l.dono_id = v_membro` → tudo `true` (inclui `troca_escopo`, RN-07, CA-08.4).
   - outro membro (só alcança conjunta): `descricao`, `valor`, `categoria_mesmo_escopo` = `true`; `data` = `not v_credito`; `troca_escopo`, `forma`, `parcelas` = `false` (CA-08.3).
5. `v_credito`: `exists (lancamento_pagamento lp join forma_pagamento f … where f.tipo = 'credito')`. Ponto de atenção: só funciona com acesso à parte privada (dentro do DEFINER); chamada como INVOKER pelo outro membro, a linha é invisível e o resultado de `data` sairia errado. Por isso: `revoke execute ... from public, anon, authenticated` (só o dono das funções a executa; o schema `app` não é exposto) e comentário curto dizendo que a função lê a parte privada e só é chamada por `api.editar_lancamento`. Se a PENDENTE de TP-0097 (coluna `no_credito`) for aprovada, trocar para a coluna compartilhada e liberar a chamada INVOKER.
6. `supabase db diff -f regra_permissoes_edicao`, `pnpm local:resetar`; `pnpm contrato:gerar` sem diff (schema `app`).

Não fazer: levantar `sem_permissao` aqui (quem decide o erro, comparando com o que mudou, é o TP-0099); `security definer` (fora da lista fechada, G-03); expor em `api`.

## 2. Plano de teste
pgTAP `backend/supabase/tests/lancamentos/permissoes_edicao.sql`, um `results_eq` por célula. Rodar a chamada com o papel dono das funções (simulando o contexto do DEFINER) e `request.jwt.claims` de A ou B para `app.membro_atual()`. Lançamentos criados na transação:
- Conjunta Pix paga por A: A → tudo `true`; B → `descricao/valor/data/categoria_mesmo_escopo` `true`, `troca_escopo/forma/parcelas` `false`.
- Conjunta Crédito 3x paga por A: B → igual, mas `data = false`; A → tudo `true`.
- Conjunta Crédito à vista paga por A: B → `data = false`.
- Individual de A: A → tudo `true`; B → `registro_invalido`.
- Receita de A: A → tudo `true`; B → `registro_invalido`.
- Simétrico com B pagador e A como outro membro (pelo menos 2 células).
- Id inexistente → `registro_invalido`; usuário sem membro → `registro_invalido` (código final: mesma PENDENTE de TP-0015).
- Catálogo: `authenticated` e `anon` sem `execute` (`function_privs_are`).
Comandos: `pnpm local:resetar`; `pnpm exec supabase test db --workdir backend` (este arquivo + `tests/seguranca/catalogo.sql`). [BD] exclusivo.
