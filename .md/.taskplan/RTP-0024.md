# RTP-0024 — Caso testes-api de `definir_preferida`: usar ids do seed

Reserva: Livre
ID no TASK.md: RTP-0024 · Lote: Refatoração Lote-11 · Agente: executor · Chapéu: Backend · Est: 0.5h · Dep: TP-0058 · Status no TASK.md: Pendente
Reqs: CA-03.4; RN-19; achado de QA de TP-0058 · Aceite: `casos/definir-preferida.test.ts` usa os ids reais do seed `03-formas` (`00000000-0000-4000-8000-000000000301/302`), A troca a preferida e volta sem erro, B recebe `registro_invalido` por uma forma que existe (de A); teste verde

## 1. Plano de execução
Origem: achado não crítico do QA de TP-0058. As constantes `PIX_NUBANK`/`OUTRA_FORMA` do caso usam o prefixo `e1000000-…` (ids dos pgTAP), que não existe no seed `03-formas` (ids `00000000-0000-4000-8000-000000000301/302`). Com a API local, o primeiro teste falharia (`registro_invalido` para A) e o segundo passaria por acaso (id inexistente), sem provar o isolamento de B. Trocar as duas constantes pelos ids do seed; conferir também o mesmo prefixo errado em `salvar-forma.test.ts` (`CONTA_DE_A`, `FORMA_DE_A`) e `salvar-conta.test.ts`, corrigindo se confirmado. Sem mudar a função.

## 2. Plano de teste
`pnpm local:resetar`; `pnpm --filter @mymoney/testes-api test -- definir-preferida` verde com a API local; B com `…0301` (existente, de A) recebe `registro_invalido`.

## 3. Plano de validação de segurança
G-05/G-04: o caso de B passa a provar que uma forma existente de A é tratada como inexistente (hoje a asserção não distingue os dois).
