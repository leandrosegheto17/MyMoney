# RTP-0060 — checar-aditiva.sh: '--' dentro de literal esconde drop/rename na mesma linha

Reserva: Livre
ID no TASK.md: RTP-0060 · Lote: Refatoração Lote-21 · Agente: executor · Chapéu: Backend (operação) · Est: 1h · Dep: TP-0109 · Status no TASK.md: Pendente
Reqs: QA de TP-0109 (achado médio); ADR-011 §4.2; G-12 · Aceite: migration com `insert into app.t values ('--'); drop table app.t;` na mesma linha é reprovada sem justificativa; caso novo no teste; 31 casos atuais verdes

## 1. Plano de execução
Origem: QA de TP-0109. `sql_sem_comentarios` remove `--[^\n]*` sem respeitar literais de string, então `'--'` apaga o resto da linha, inclusive um `drop`. Reproduzido com repositório git temporário (migration passou como "aditiva"). Ajustar o remove-comentários para ignorar `--` e `/*` dentro de literais `'...'` (e, se simples, de `$$...$$`), sem mudar o resto da checagem. Falso positivo (drop dentro de corpo $$) continua exigindo justificativa: aceitável.

## 2. Plano de teste
Caso novo em `checar-aditiva.test.sh`: migration com `'--'` seguido de `drop table` na mesma linha falha; `-- drop` em comentário real continua passando; 31 casos atuais verdes.

## 3. Plano de validação de segurança
Fecha um bypass da regra G-12 por literal; sem mudança de superfície (nome de migration segue sem avaliação como código).
