1. `Campo.tsx`: props `rotulo`, `ajuda?`, `erro?`, `id?` (`useId` por padrão) e um *render prop* que recebe `{ id, 'aria-invalid', 'aria-describedby' }` para o controle. `aria-describedby` = id do erro, depois id da ajuda (ordem do mockup); `aria-invalid="true"` só com erro. Erro: `<p class="campo-erro">` com ícone `alerta` (sem `role=alert`: o anúncio vem do foco no campo; quem precisar de anúncio, como a T03, decide na própria tarefa).
2. `CampoTexto.tsx` (`input type=text`, `autoComplete`, `type` email/password permitidos para a T01), `CampoData.tsx` (`type=date`, valor `YYYY-MM-DD`; o "hoje" padrão é de quem chama, via `hojeEmSaoPaulo` do TP-0024), `Selecao.tsx` (`select` nativo, `opcoes: {valor, rotulo}[]`). Os três usam `Campo`. Todos aceitam `ref` (React 19) e `desabilitado`.
3. `Interruptor.tsx`: `label.interruptor` > texto (+ ajuda opcional) + `input type=checkbox role=switch` (o rótulo envolve o controle; sem `Campo`).
4. `Botao.tsx`: `variante: principal|secundario|perigo|texto`, `bloco?`, `icone?`, `tipo` (padrão `button`), `salvando?`. Com `salvando`: texto "Salvando…", ícone `recarregar` girando, `aria-disabled="true"` (o foco fica; mockup) e clique/submit bloqueados no handler (impede envio duplo).
5. `focarPrimeiroErro.ts`: `focarPrimeiroErro(raiz: HTMLElement): boolean` foca o primeiro `[aria-invalid="true"]` na ordem do DOM.
6. CSS Modules transcritos (um por componente; `Campo.module.css` com `.campo`, `.campo-ajuda`, `.campo-erro`, `.entrada` compartilhada pelos três controles). `.formulario` e `.acoes-formulario` são da página: não criar componente sem uso (YAGNI); a vitrine usa os mesmos valores via CSS próprio de ensaio.
7. Ordem TDD: testes de unidade → componentes → vitrine `e2e/vitrine/formulario.html` (+ `.tsx`) → e2e.

Não fazer: `CampoValor` (TP-0035), `ChipOpcao`/segmentado (outras tarefas), validação de regra (é do servidor e de cada tela).

## 2. Plano de teste
- `componentes/base/*.test.tsx` (Vitest + Testing Library): cada campo achado por `getByLabelText(rotulo)`; sem erro: sem `aria-invalid`, `aria-describedby` só com a ajuda; com erro: `aria-invalid="true"`, `aria-describedby` = "erro ajuda" e o texto do erro lido por `toHaveAccessibleDescription`; `Selecao` dispara mudança; `Interruptor` tem `role=switch` e alterna; `desabilitado` aplica `disabled`.
- `Botao.test.tsx`: variantes geram a classe certa; `salvando` mostra "Salvando…", `aria-disabled="true"`, clique não chama `onClick` e submit do form não dispara 2 vezes.
- `focarPrimeiroErro.test.ts`: 3 campos, 2º e 3º inválidos → foco no 2º, retorna `true`; nenhum inválido → `false`.
- `e2e/formulario.spec.ts` (Playwright, vitrine): **estado manual `formulario--salvando`**: preencher, clicar "Salvar", o botão vira "Salvando…" com `aria-disabled`, segundo clique não envia de novo (contador na vitrine); print anexado. Erro: submeter vazio → foco no 1º campo inválido. Alvos ≥ 44 px; `semViolacoesGraves` nos estados normal, erro e salvando, nos 2 tamanhos.
- Comandos: `pnpm --filter @mymoney/web test -- src/componentes/base` e `pnpm --filter @mymoney/web exec playwright test e2e/formulario.spec.ts`.
