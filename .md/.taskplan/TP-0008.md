## 1. Plano de execução
**Reaproveitamento:** usar o projeto da CLI em `backend/supabase/` (TP-0002), o `backend/README.md` e o `backend/.env.example` (TP-0002) e o `.github/workflows/ci.yml` (TP-0007). Criar aqui o módulo comum de confirmação digitada `backend/operacao/comum/confirmar.sh` (função `confirmar_digitado <texto_esperado>`: lê uma linha do stdin, entrada vazia/EOF/diferente → retorna ≠ 0), porque o TP-0009 (`setup/limpar-supabase.sh`) precisa da mesma regra (G-14). O ajudante de teste com comandos simulados no `PATH` também fica comum: `backend/operacao/comum/testes/simular.sh`.
**Camada:** `backend/operacao/deploy/` (scripts de operação, SDD §2 árvore alvo); comum em `backend/operacao/comum/`. Não é pacote JS: não criar `package.json` nem dependência nova.
**Referência visual:** não se aplica.
Passos (TDD: escrever primeiro `backend/operacao/deploy/testes/migrar.test.sh`, ver §2):
1. `comum/confirmar.sh` + teste; `set -euo pipefail` em tudo.
2. `deploy/migrar.sh`, em ordem: (a) `git status --porcelain` não vazio → aborta; (b) commit `HEAD` precisa estar no remoto e ter run do workflow `ci` com `conclusion=success` (`gh run list --commit <sha> --workflow ci.yml --json databaseId,conclusion`) e o job `isolamento` com sucesso (`gh run view <id> --json jobs`); (c) pasta das cópias = `MYMONEY_COPIAS_DIR` (padrão `$HOME/mymoney-copias`); aborta se ficar dentro do repositório (`git rev-parse --show-toplevel`); (d) `supabase db dump --linked -f <dir>/<data>-schema.sql` e `--data-only -f <dir>/<data>-dados.sql`, falha → aborta; (e) `supabase db push --linked --dry-run` exibido; (f) `confirmar_digitado <ref do projeto>` (ref lido de `supabase/.temp/project-ref`); (g) `supabase db push --linked`; (h) imprime os comandos de restauração (`psql` com as duas cópias) e o lembrete de apagar a cópia depois de confirmada (SDD §7 "Criptografia").
3. Parâmetro `--db-url <url>` repassado a dump/push para o ensaio local (`postgresql://postgres:postgres@127.0.0.1:54322/postgres`); `--db-url` só aceita host `127.0.0.1`/`localhost` (o alvo de produção é sempre `--linked`).
4. CI (`.github/workflows/ci.yml`, arquivo do TP-0007, edição mínima): passo `shellcheck backend/operacao/**/*.sh` e passo que roda `bash backend/operacao/deploy/testes/migrar.test.sh`.
5. `backend/README.md`: uso, pré-requisitos (`supabase link`, `gh auth login`), ensaio local passo a passo, restauração. `backend/.env.example`: `MYMONEY_COPIAS_DIR` (sem valor real).
Atenção: o script nunca lê senha nem token do repositório (SDD §7 "Serviço a serviço"); nada de ID de tarefa nos scripts (grep do CI).
RESOLVIDO (Coordenador, 2026-10-09): o script exige o run do `ci` verde **e** cada job de uma lista fixa escrita no topo do script (`JOBS_EXIGIDOS=(base)` nesta tarefa). O TP-0018 acrescenta `banco` e `isolamento` à lista quando cria esses jobs, e a partir daí a exigência vale sempre (sem checagem condicional, sem exceção nova). O TP-0011 roda só com `base`, o que já está coberto pela D-11. Registrado no aceite do TP-0008 e do TP-0018 (TASK.md) e na D-11. No passo 2(b), conferir com `gh run view <id> --json jobs` cada nome de `JOBS_EXIGIDOS`.
