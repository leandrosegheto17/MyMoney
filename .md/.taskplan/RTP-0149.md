# RTP-0149 — E2E @integracao da receita sem trava de host local

Reserva: Livre
Status-local: Concluída · QA ✔
Origem: DevSecOps de TP-0116 (não crítico 1). `e2e/integracao/lancar-receita.spec.ts` grava no Supabase apontado por `VITE_SUPABASE_URL` (de `.env.local`) sem conferir que o host é local, e tem a senha do seed como padrão embutido (`?? 'senha-local-123'`). Se `.env.local` apontar para um projeto remoto, o teste lança receita real com esse login.

## 1. Plano de execução
Antes de entrar, o spec valida o ambiente com `lerAmbienteIntegracao` (`e2e/integracao/apoio/ambiente.ts`, já especificado por `ambiente.test.ts`; criar se ainda não existir): recusa host que não seja `127.0.0.1`/`localhost`. Tirar o padrão embutido da senha: `TESTE_SENHA` vem do ambiente (`backend/.env.example`). Sem mudar o código da aplicação.

## 2. Plano de teste
`vitest e2e/integracao/apoio/ambiente.test.ts` passa; `playwright test --grep @integracao` com `VITE_SUPABASE_URL=https://exemplo.invalid` falha antes de qualquer gravação; com o Supabase local, passa.

## 3. Plano de validação de segurança
G-06: nenhuma gravação fora de localhost; nenhuma credencial padrão no código do spec.

## 4. Resultado da execução
**Feito:** criado `e2e/integracao/apoio/ambiente.ts` (`lerAmbienteIntegracao`): recusa URL ausente, inválida ou fora de `127.0.0.1`/`localhost` (comparando o hostname já interpretado) e exige `TESTE_EMAIL_A/B/SEM_MEMBRO` e `TESTE_SENHA` com o nome da variável no erro. A trava de host foi extraída de `e2e/apoio/limpeza-local.ts` (`ehHostLocal`, `lerEnvLocal`) e a limpeza passou a usá-la; o ambiente a reaproveita, sem duplicar. O spec chama `lerAmbienteIntegracao` no topo do arquivo, antes de qualquer teste, e não tem mais `?? 'senha-local-123'` nem e-mail padrão. `vite.config.ts` (projeto `arquivos`) passou a incluir `e2e/**/*.test.ts` para o vitest achar `ambiente.test.ts`. Código da aplicação intocado.

**Testes rodados:**
- `pnpm exec vitest run e2e/integracao/apoio/ambiente.test.ts`: 5 passando.
- `VITE_SUPABASE_URL=https://exemplo.invalid PORTA=5293 playwright test --grep @integracao ...`: spec derrubado ao carregar ("fora de 127.0.0.1/localhost"), nenhum teste executado, nenhuma gravação.
- `PORTA=5293 playwright test --grep @integracao e2e/integracao/lancar-receita.spec.ts` (Supabase local, TESTE_* exportados de `backend/.env.example`): 1 passando; a limpeza apagou a receita criada.

**Notas/riscos:** o spec agora exige `TESTE_*` exportadas no shell (documentado no cabeçalho do spec). Ao rodar a variante com URL inválida o Playwright deixou o vite da porta 5293 no ar com a URL inválida; um rerun reaproveitou esse servidor e falhou ao carregar a tela até eu encerrar o processo (artefato do teste manual, não do código). Checklist de convenções: sem trecho copiado, sem ID de tarefa em código/comentário, comentário do cabeçalho do spec atualizado, arquivos abaixo de 300 linhas, sem import furando fronteira; tarefa não é de tela (sem comparação visual).

**Arquivos alterados:**
- frontend/web/e2e/integracao/apoio/ambiente.ts
- frontend/web/e2e/integracao/lancar-receita.spec.ts
- frontend/web/e2e/apoio/limpeza-local.ts
