# RTP-0072 — checar-aditiva.sh: falha aberta quando o perl existe mas falha em execução

Reserva: Livre
ID no TASK.md: RTP-0072 · Lote: Refatoração Lote-21 · Agente: executor · Chapéu: Backend (operação) · Est: 0.5h · Dep: RTP-0060 · Status no TASK.md: Pendente
Reqs: QA de RTP-0060 rodada 2 (achado médio); G-12; falhar fechado · Aceite: perl que sai com erro durante a varredura faz o script sair com código diferente de 0 e não aprova a migration; caso novo no teste (perl falso que sai 1, migration com drop); 62 casos atuais verdes

## 1. Plano de execução
A rodada 2 de RTP-0060 só checa `command -v perl`. Se o perl existe mas falha em execução (reproduzido com um `perl` falso no PATH que imprime erro e sai 1), `sql="$(sql_sem_comentarios ...)"` roda dentro de `achados_nao_aditivos`, que está num pipeline em `$(...)` de `main`; o status do perl se perde e o script imprime "ok: m.sql é aditiva", rc 0, para uma migration com `drop table x;`. Propagar o status da varredura (gravar o resultado da varredura em variável com teste explícito de status, e sair 2 com mensagem se falhar), de modo que a falha do perl nunca vire aprovação.

## 2. Plano de teste
Caso novo em `checar-aditiva.test.sh`: PATH com um `perl` falso que sai 1, migration com `drop` e migration aditiva; ambas saem com código diferente de 0 e sem "é aditiva". 62 casos atuais verdes.

## 3. Plano de validação de segurança
Fecha a falha aberta residual da checagem G-12 (varredura que falha por qualquer motivo precisa reprovar, não aprovar).

## 4. Resultado da execução
**Feito.** Em `achados_nao_aditivos`: reprova (return 2) se o arquivo não é regular/legível (cobre symlink pendente), se o perl sai com status != 0 (erro ou sinal) ou se não produz saída para arquivo não vazio. Em `main`, o status é capturado com `if ! bruto="$(...)"` (antes se perdia dentro do pipeline) e vira `reprovar` (rc 1, "falha fechada"); o pipe `sort|paste` agora roda só depois, sobre a variável. Migration vazia continua aprovada.

**Arquivos:** `backend/operacao/deploy/checar-aditiva.sh` (editado); `backend/operacao/deploy/testes/checar-aditiva.falha-fechada.test.sh` (novo, 10 casos). Os casos novos foram para arquivo novo para não aumentar o `checar-aditiva.test.sh` (417 linhas, a RTP-0073 divide). O teste novo aceita `CHECAR_ADITIVA=<script>` para rodar contra outra versão.

**Casos:** perl falso que sai 1 / morre por SIGKILL / sai 0 sem saída, cada um com migration com drop e migration aditiva (6); symlink pendente com drop ao lado e sozinho (2); chmod 000 (só roda se não for root; pulado aqui, uid 0); migration vazia aprovada; aditiva com perl real aprovada.

**Comandos/saída:** contra o script antigo (git show HEAD) o teste novo dá 2/10 (8 falhas, inclusive rc 0 para drop com perl que sai 1); com o novo, 10/10. `checar-aditiva.test.sh`: 62/62. `migrar.test.sh`: 30 casos, 0 falhas. shellcheck 0.x via `pip install --target` fora do repo, `find backend/operacao -name '*.sh' -print0 | xargs -0 shellcheck -x`: só os 2 SC1091 de host-local.test.sh (esperados).
