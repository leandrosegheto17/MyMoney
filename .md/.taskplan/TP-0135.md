**Camada:** banco, `backend/supabase/schemas/app/funcoes/orcamentos_escopo.sql`, `.../situacao_orcamento.sql`, `.../orcado_realizado.sql` (funções internas, não expostas; SDD §2 "Camadas do banco"); pgTAP em `backend/supabase/tests/orcamento/`.
**Referência visual:** não se aplica.

1. TDD: `tests/orcamento/situacao_orcamento.sql` e `tests/orcamento/orcado_realizado.sql` primeiro.
2. `app.situacao_orcamento(p_orcado bigint, p_realizado bigint) returns jsonb` (`sql immutable`, `search_path = ''`): `{percentual, situacao}`; `percentual = round(100.0 * realizado / orcado)::int` (o JSON mostra 110,83% → 111); situação pela razão **exata** em inteiros, sem usar o percentual arredondado: `realizado * 100 < orcado * 80` → `dentro`; `realizado <= orcado` → `atencao`; senão `estourado` (valores de `respostas/orcamento-mes.json`). Interpretação registrada: 79,99% aparece "80%" com "Dentro".
3. `app.orcamentos_escopo(p_mes date, p_escopo text) returns setof app.orcamento` (`sql stable security invoker`): `mes = app.inicio_mes(p_mes) and escopo = p_escopo and (p_escopo = 'conjunto' or dono_id = app.membro_atual())` (RN-16e: além da RLS).
4. `app.orcado_realizado(p_mes date, p_escopo text) returns jsonb` (`stable security invoker set search_path = ''`, 1ª linha `app.membro_atual()`):
   - `linhas`: cada orçamento de `app.orcamentos_escopo` + `nome` da categoria + `realizado_centavos = coalesce(Σ valor_centavos de app.parcelas_mes(p_mes) com tipo = 'despesa' and categoria_id = o.categoria_id, 0)` || `app.situacao_orcamento(...)`; ordem `percentual desc, nome` (a do JSON). Chaves = as de `linhas[]` do JSON.
   - Individual (RN-16c): só `escopo = 'individual' and dono_id = membro`; a minha parte nas conjuntas não entra.
   - `total`: `orcado_centavos = Σ orçado das linhas`, `realizado_centavos` (ver PENDENTE) e `app.situacao_orcamento`; `null` quando o escopo não tem orçamento no mês (`orcamento-mes-vazio.json`). `resultado` e `parcial` ficam para TP-0136/TP-0139.
   PENDENTE: o realizado do **total** de escopo soma só as categorias orçadas ou todas as despesas do escopo no mês (Total do casal / Meu individual)? O mockup não distingue (todas as categorias estão orçadas), mas a RN-16d ("orçamento conjunto − Total do casal") pede todas. Proposta: todas as despesas do escopo, para o resultado da casa bater com a RN-16d e o `realizado` do resumo bater com `total_centavos`/`meu_individual_centavos`.
5. Privilégios padrão de função (TP-0003); `supabase db diff -f orcado_realizado`; `pnpm local:resetar`.

Não fazer: ler `valor_total_centavos` (G-11); repetir o filtro de mês fora de `app.parcelas_mes`; resultado/parcial; `security definer`; ID de tarefa no SQL.
