# RTP-0130 — pagar_ocorrencia: limitar a data do pagamento a uma faixa plausível

Reserva: Livre
Origem: DevSecOps de TP-0132 (baixa). `api.pagar_ocorrencia` usa `p_data` sem validar faixa (`coalesce(p_data, app.hoje())`): o cliente só oferece "hoje" como padrão, mas uma chamada direta grava data da operação arbitrária (ex.: ano 9999), distorcendo saldo/extrato do próprio pagador (sem vazamento entre membros). G-07: o servidor é quem valida.

## 1. Plano de execução
Em `backend/supabase/schemas/api/funcoes/pagar_ocorrencia.sql`, recusar `v_data` fora de uma faixa plausível (limite superior perto de `app.hoje()`, inferior fixo) com a exceção de regra já usada pelo projeto; gerar a migração; teste de API com data absurda.

## 2. Plano de teste
`npx vitest run testes-api/casos/pagar-ocorrencia.test.ts` (variáveis do `.env.example`): data 9999-12-31 e 1900-01-01 recusadas; data de hoje aceita.

## 3. Plano de validação de segurança
Confirmar que a recusa não vaza dado de outro membro e que o reenvio idempotente continua funcionando.
