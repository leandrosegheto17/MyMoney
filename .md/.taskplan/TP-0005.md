**Camada:** `backend/supabase/schemas/api/funcoes/ping.sql`; pgTAP em `backend/supabase/tests/seguranca/`.
**Referência visual:** não se aplica.

1. TDD: escrever `tests/seguranca/01-anon-so-ping.sql` e `tests/api/ping.sql` (passo de teste) e ver falhar.
2. `ping.sql`: `create or replace function api.ping() returns integer language sql stable security invoker set search_path = '' as $$ select 1 $$;` + `grant execute on function api.ping() to anon, authenticated;` + `grant usage on schema api to anon;` (o TP-0003 deixou `anon` sem `usage` em `api`; sem isso o PostgREST nega a chamada). Sem `app.membro_atual()` na primeira linha: é a exceção natural da TASK 1.3 (o `anon` não é membro; ADR-009 §1: sem acesso a tabela).
3. Migration: `pnpm exec supabase db diff --workdir backend -f funcao_ping`; conferir se os dois `grant` vieram (registrado no README pelo TP-0003); completar à mão o que faltar, em `begin; … commit;`. `pnpm local:resetar` do zero.
4. Se o comportamento observado sobre o `db diff` divergir do que o TP-0003 anotou no `backend/README.md`, corrigir a anotação (edição mínima).
5. NÃO fazer: dar ao `anon` qualquer outro `grant` (tabela, view, sequência), retornar `void`/`json`, gravar algo (o ping não pode ter efeito colateral).
