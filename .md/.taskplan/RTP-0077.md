# RTP-0077 — Fila: alinhar ItemFila ao fila-offline.json do mockup

Reserva: Livre
Status-local: Concluída · aguarda QA

## 1. Plano de execução
Origem: QA do TP-0077. `ItemFila.criadoEm` é número (ms) e `motivo` é opcional; `.md/mockup/respostas/fila-offline.json` usa `criadoEm` ISO e `motivo: null`. O plano exigia manter os dois iguais, com teste `satisfies ItemFila[]`. Escolher um formato (ajustar o tipo ou o JSON, avisando o TP-0089) e criar o teste de tipo.

## 2. Plano de teste
Teste de tipo `satisfies ItemFila[]` sobre o JSON; `typecheck` limpo.

## 3. Plano de validação de segurança
Não se aplica (sem dado sensível no fixture).

## 4. Resultado da execução
Escolhido o formato do tipo `ItemFila`: ajustado o JSON do mockup (`criadoEm` agora em ms epoch = 1791544500000, equivalente a 2026-10-09T08:15:00-03:00; campo `motivo: null` removido, pois `motivo` é opcional). Nenhum código consumia o JSON ainda; TP-0089 deve ler `criadoEm` como número.
Teste: `frontend/web/src/dados/fila/fixtureMockup.test.ts` (chaves checadas com `satisfies readonly (keyof ItemFila)[]`, `criadoEm` number, `situacao` válida, sem `motivo` quando aguardando, `p_id === id`). Um `satisfies ItemFila[]` direto sobre o JSON não serve: o JSON importado alarga `situacao` para `string`, e os testes ficam fora do `tsc` do pacote.
Arquivos: `.md/mockup/respostas/fila-offline.json` (editado), `frontend/web/src/dados/fila/fixtureMockup.test.ts` (novo).
Comandos: `npx vitest run src/dados/fila/fixtureMockup.test.ts` -> 1 passou; `npx tsc --noEmit -p tsconfig.json` -> limpo.
Convenções: sem duplicação, sem IDs em comentários, arquivos curtos.
Risco: o JSON do mockup mudou (fonte aprovada); `fila-offline-vazia.json` não afetado.
