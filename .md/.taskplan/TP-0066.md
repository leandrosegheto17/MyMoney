**Referência visual:** não se aplica (a prévia "Ajuste de − R$ 12,30" de `.md/mockup/telas/conta--sucesso.html` é consumida no TP-0071).

1. TDD: pgTAP e caso de `testes-api` primeiro.
2. `api.ajustar_saldo(p_conta_id uuid, p_saldo_real_centavos bigint, p_simular boolean default false) returns bigint` (diferença com sinal, em centavos; positivo = entrada). Não há JSON no mockup para o retorno: tipo escalar é interpretação registrada em `## 4`; `pnpm contrato:gerar` publica o tipo para o TP-0069.
3. Fluxo: membro nulo → `registro_invalido` (RESOLVIDO no TP-0015, SDD §2); `p_conta_id` ou `p_saldo_real_centavos` nulo → `valor_invalido` (saldo real negativo é aceito: conta no vermelho); `select … from app.conta where id = p_conta_id for update` (trava a conta: dois ajustes simultâneos não gravam a diferença duas vezes; a política de `update` do dono permite) → não achou → `registro_invalido`; `v_dif := p_saldo_real_centavos - app.saldo_conta(p_conta_id)`.
4. `if p_simular or v_dif = 0 then return v_dif`. Senão `insert into app.movimento_conta (conta_id, tipo, sentido, valor_centavos, data) values (p_conta_id, 'ajuste', case when v_dif > 0 then 'entrada' else 'saida' end, abs(v_dif), app.hoje())`; `return v_dif`. Diferença 0 não grava: um reenvio do mesmo saldo real devolve 0 e não duplica (idempotência natural, registrar).
5. Conta arquivada: ajuste permitido (histórico continua corrigível; interpretação registrada).
6. `revoke execute … from public, anon; grant execute … to authenticated` (conferir os privilégios padrão do TP-0003). `supabase db diff -f api_ajustar_saldo`; `pnpm local:resetar`; `pnpm contrato:gerar` e versionar `backend/contrato/src/banco.ts`.

Não fazer: gravar `lancamento`/`parcela` (ajuste não é receita nem despesa, I-14); calcular saldo aqui; aceitar data ou dono por parâmetro; `security definer`; ID de tarefa no SQL.
